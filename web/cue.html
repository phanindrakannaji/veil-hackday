Presenter script

~5 min pitch · live demo

Thesis: programmable consent for cameras — Pass → bind → enforce → rights graph → revoke. Not “AI blur as the product.”

Prep

Before you start

  1. Mac Terminal: Veil server running · keep that window open
  2. Console → Start clean demo (or Wipe everything)
  3. Mac /camera · iPhone /pass · iPad /console · this tab /cue
  4. Drag the INTERNAL box onto your face
Live clock

Timed beats

0:00 “Cameras capture by default. Veil makes consent programmable.”
Point at dual panes — INTERNAL clear, PUBLIC already blurring Unknown.
0:30 “Attendee issues a Veil Pass — a short-lived credential, not a face ID.”
iPhone: Pass shows · tap Allow.
0:50 “We associate Pass ↔ person-track. Same decide() for livestream and later export.”
Mac: Bind latest Pass · PUBLIC flips to allow ≤1s.
1:20 “Capture once. Rights travel with the media.”
Mac: Capture clip.
1:40 “Organizer changes promo policy — re-export is blocked or allowed with a receipt.”
iPad: Deny promo → re-export · then Allow promo → re-export · show receipts / graph. Optional: Explain this decision (OpenRouter) for judges.
2:20 “Revoke and the live view goes deny — consent isn’t one-and-done.”
iPhone: Revoke · PUBLIC → deny.
2:40 “Beachhead: conference / venue organizers. Capture Enforcement SDK + Media Rights Graph — Neo4j when available, memory fallback for the live demo.”
One sentence ask: event pilot vs multi-venue rollout. Console chip shows Rights graph · Neo4j.
3:10 “We built this with Fabric — an agentic engineering control plane.”
Show FACTORY-BOOTSTRAP: impact → contracts → workers → Sentinel gates → READY_TO_MERGE.
4:20 Close: “Policy layer for cameras + control plane for agents. Who wants a pilot?”
Objections

If asked “is that face AI?”

“We run on-device face detection so boxes follow people in a crowd. Identity is still the Pass — not a face database. Novelty is policy + receipts + dual views.”
